# Evaluation protocol

The dataset is the existing 665-table cohort from the 1,651-page OmniDocBench release. Its dataset revision is `aa1ee96d106dbe53d0ae59474d75c6e6d9b53fec`, and the reference annotation SHA-256 is `a45cd84b04ad8b793e775089640e6b681209abea33ead54c1828ddca35fae496`. The unchanged official evaluator commit is `7ddb8df411ad9bd2fff139acafe0ed16aa1694fe`. This is the pinned evaluator used for the existing B0–B3 table-recognition experiment. Dataset and evaluator identifiers are recorded independently because upstream version labels have evolved.

B0 is the original Xiaomi BF16 snapshot. The global prompt, greedy decoding, maximum output length of 16,384, repetition penalty 1.0, EOS, tokenizer and official HTML serializer are common across methods. Existing B0 predictions are reused after provenance validation. Additional views use the same model and decoding protocol.

TEDS and TEDS-S use the unchanged OmniDocBench HTML normalization and `call_TEDS` scorer in its pinned runtime image. The per-table timeout is 120 seconds and scoring uses six CPU workers, matching the historical experiment. Strict EM compares the normalized HTML strings. Structure-Only EM compares the same normalized table tree with cell content removed and rowspan/colspan retained. CER is the total Levenshtein edits over normalized cell text divided by total reference characters.

Latency includes the recorded original B0 latency plus the new method's elapsed time, including recorded failed attempts and retries. Incremental latency is also reported, because global outputs are reused from cache. Average Model Calls includes one original global call plus all additional generation calls, including calls from recorded failed attempts. Per-sample records also expose the successful attempt's cost separately. The one-time B0 compatibility replay is an audit expense outside these per-method averages.

Successful Refinement Rate is the fraction of changed tables with positive paired TEDS difference. Harmful Modification Rate uses a negative paired difference among changed tables. Both are null when no table changes. No-change Rate uses all 665 tables as denominator. Failure Rate reports operational failures or unavailable verification. Scoring covers the complete common set before direct gains are calculated. A page-level paired bootstrap uses seed 320 and 10,000 draws.

An output that reaches the length limit is retained and scored, following the original experiment's policy, with the truncation flag reported. Failed inference attempts are retried at most three times per invocation and preserved separately. An exhausted failure stops the worker and requires the documented resume command. Successful outputs remain immutable. Official scoring retries only failed or uncommitted rows, preserves successful score lines, and stops final aggregation if the bounded retries are exhausted. A zero score alone never triggers a retry.

Runtime and backend exceptions enter the bounded retry path. Deterministic unavailable verification, such as unsupported glyphs or an invalid predicted structure, returns the original B0 output as required by the method's fallback rule. This terminal fallback stores the error, is counted in Failure Rate, and is explicitly non-retryable under the same frozen inputs. It is distinct from an interrupted model or render backend call, which has no committed success record and is retried.

Historical scores were already present in the project conversation before this task. Method development uses synthetic images and mock predictions, and configurations are published before new inference. The method APIs receive no ground truth, metric scores or other methods' outputs. Operational gate checks inspect coverage and failure counts. This establishes a fixed prospective comparison with an explicitly acknowledged prior view of historical baseline results.

Per-table generation records are in each method's `predictions` directory. Once scoring finishes, `samples` contains the complete record with metrics. `metrics.json` contains the aggregate and paired analysis. Every path under `experiments` is excluded from publication.
