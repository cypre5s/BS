# Render-guided verification

Method C accepts the cached B0 prediction and renders its official HTML on the CPU. `RenderGuidedVerification.run` can also request a global prediction through the common runtime when no cached prediction is supplied. It records that call in the same way as the other methods. No model is constructed by the method.

`xiaomi_runtime.otsl.to_html` invokes the byte-identical Xiaomi deployment parser and serializer used by B0. The preferred skill converter has different escaping and span behavior, so the shared runtime uses the official deployment converter to preserve the experiment's parser identity. Method C accesses the official `parse_grid` and `pad_rows` for any accepted edit. HTML inspection checks the resulting topology and never replaces OTSL parsing rules.

`HTMLRenderer` uses WeasyPrint 70.0 to lay out HTML/CSS, emits an in-memory PDF, and rasterizes the table with PyMuPDF. Its layout audit checks cell count, cell order, row and column counts, rowspan and colspan. Text content, including blank cells and inline character sequences, is checked before and after HTML sanitization. Tables that span multiple render pages, exceed the page rectangle, or contain unsupported glyphs return the baseline through an explicit fallback. WeasyPrint layout internals are version-dependent, which is why the dependency is pinned. [WeasyPrint API stability](https://doc.courtbouillon.org/weasyprint/stable/api_reference.html#api-stability)

Fonts are runtime resources outside Git. Configure `font_paths` or `BS_RENDER_FONT_PATHS` to include a font covering the table's script. DejaVu Sans is discovered on Linux, and the local evaluation also provisions Noto Sans CJK SC. The renderer audits font character maps before use. Its URL fetcher accepts only the configured local font files. Rendered images and PDFs are temporary in-memory objects.

Verification extracts long horizontal and vertical dark runs from the original crop. Runs are clustered into ordered grid axes. Their count must agree with the predicted table and their extent must define a stable outer frame before a structural edit is considered. The rendered image must also have a stable frame. Comparisons use ordered boundaries and cell spans, so font size, font family, line thickness and background colors do not enter as pixel differences.

The current repair rule handles a specific case. A predicted blank merged cell can be split into blank unit cells when all its proposed internal separators have at least 95% visible line support in the source image and the remaining interior has at most 0.2% dark pixels. A text-bearing merged cell is retained. The whole source grid must align first, so borderless tables and ambiguous axis counts retain B0. Fixed thresholds were selected from public HTML syntax and generated geometric test fixtures before benchmark execution.

An accepted candidate is reconstructed from the official token grid. The code checks that it matches exactly the expected split locations and preserves the ordered nonblank cell content. It then renders the candidate again and repeats verification. Acceptance requires fewer contradicted boundaries and no remaining proposed blank-merge repair. Failure at either stage retains the original raw OTSL and HTML. This implementation makes no second visual model request and does not generate text or amounts.

`tests/test_renderer.py` contains twelve independently authored examples of public HTML table syntax. They cover a normal cell, a blank cell, rows, columns, rowspan, colspan, combined spans, row groups, entity characters, inline formatting, line breaks and merged blank cells. Every example is actually rendered and its layout checked. They follow the standard table model of a rectangular grid fully covered by non-overlapping cells. [HTML table model](https://html.spec.whatwg.org/multipage/tables.html#table-model)

`tests/test_structure_checker.py` exercises supported repairs, genuine merges, visible-ink vetoes, borderless fallback, inconsistent grid fallback, font-size invariance, color invariance, content preservation, shared runtime calls and second-verification rollback. All inputs in these tests are CPU-generated syntax and geometry fixtures. The method reads no benchmark annotations or evaluation metrics.

Method C imports only the shared runtime and its own render-verification package. It uses no multi-resolution candidates and no region-selection module. On the real benchmark, acceptance rate and improvement remain measured outcomes of the independently frozen evaluation.
